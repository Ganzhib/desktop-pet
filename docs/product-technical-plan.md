# 桌面宠物产品与技术二开规划书

> 适用仓库：Ganzhib/desktop-pet。文档基于该仓库 main 分支提交 85896750a3e4198c278e443efe77e58142aa9709，以及参考仓库 Ganzhib/deskcat 的提交 b5718472223bdb23d01abf92dae7bbd8d7de39b1。产品名称和原创角色形象在发布前确定；统一工具入口已确定为 https://next.ganzhibin.icu/ 。

## 1. 产品目标与约束

桌宠是一款完整、永久免费、无需登录即可使用的桌面陪伴产品。用户可以在工作间隙与宠物互动、切换角色、使用专注提醒，也能从明确的“我的工具”入口前往“淘气工具铺”，再选择简历、画图等独立产品。商业化发生在那些独立产品中，桌宠内不设置付费墙、付费角色、订阅、广告或强制跳转。

产品成功依赖两件事：用户愿意长期保留桌宠；有相应需求时，能主动进入工具铺并找到合适的简历或画图产品。推广入口只能由用户主动打开，不能打断当前工作或宠物互动。

### 目标用户与场景

| 用户 | 主要需求 | 桌宠提供的价值 |
| --- | --- | --- |
| 日常办公和学习用户 | 轻度陪伴、短暂放松、专注提醒 | 好看的角色、及时的动作反馈、安静模式 |
| 正在求职的用户 | 快速开始制作或修改简历 | 从“我的工具”打开淘气工具铺，再选择简历工具 |
| 有画图需求的用户 | 快速开始创作 | 从“我的工具”打开淘气工具铺，再选择画图工具 |

### 产品原则

- 首次启动直接出现宠物；基础玩法不依赖账号、网络、模型 API 或复杂设置。
- 可随时拖动、缩放、静音、暂停活动和退出；全屏或专注时减少干扰。
- 宠物角色和工具入口分开设计。外部入口清楚说明用途，由用户主动点击。
- 不扫描用户屏幕、窗口内容、文件和浏览记录来推断需求。
- 所有桌宠角色、装饰、互动与功能免费。未来新增内容也遵守这一约束。

## 2. 源码基线与二开方式

| 仓库 | 当前可复用能力 | 二开处理 |
| --- | --- | --- |
| [Ganzhib/desktop-pet](https://github.com/Ganzhib/desktop-pet) | Electron 跨平台打包、透明宠物窗口、角色包、拖拽、菜单、专注提醒、可选聊天和语音、多语言、现有检查与冒烟测试 | 作为唯一主工程；保留当前角色包、设置、聊天和 IPC 结构 |
| [Ganzhib/deskcat](https://github.com/Ganzhib/deskcat) | 心情与行为模型、游走、动作反馈、托盘及鼠标穿透的实现思路 | 参考纯行为逻辑与交互体验，按主工程结构重新实现；不直接合并整屏覆盖窗口 |

主工程目前的宠物是小型透明 BrowserWindow；DeskCat 使用覆盖整个主屏幕的透明窗口，并在渲染进程启用 Node 集成、关闭上下文隔离。二开继续使用主工程的 preload 与 IPC 边界，宠物游走通过移动小窗口实现，不复制 DeskCat 的整屏窗口和 WebPreferences 配置。相关源码：[主工程窗口与 IPC](../src/main.js)、[preload API](../src/preload.js)、[角色渲染](../src/renderer.js)、[DeskCat 行为模型](https://github.com/Ganzhib/deskcat/blob/main/src/renderer/behavior-controller.js)。

主工程当前首次启动会调用 maybeShowInitialPersonaSettings 自动打开人物设置。调整为首次启动直接显示宠物，聊天和人物设置从菜单主动进入；现有聊天与语音能力保留为可选功能。

## 3. 首版用户流程

1. 安装并启动：显示一个具有明确授权的默认角色，保持原有窗口交互。首次启动不弹设置窗口，不请求登录。
2. 轻度互动：单击、双击、长按、拖拽分别给出即时且可区分的动画反馈；宠物偶尔自行待机或短距离游走。
3. 控制干扰：右键菜单可暂停自主活动、静音、调整大小、切换置顶和退出。用户进入专注模式时，宠物停止游走及主动发声；退出后恢复。
4. 发现工具：右键菜单的“我的工具”下展示“打开淘气工具铺”，说明其中可找到简历、画图等工具。点击后用系统默认浏览器打开 https://next.ganzhibin.icu/ ；桌宠继续运行。
5. 返回使用：从外部产品回到桌面后，桌宠按原状态继续。首版不要求两个产品提供登录联动或回调。

统一入口是已经上线的淘气工具铺首页。后续如需从桌宠直达某个具体产品，先确认该产品的正式落地页和链接用途，再新增独立入口；不要用 GitHub 仓库页代替产品页面。

## 4. 功能范围与优先级

### P0 首个可发布版本

- 原创或明确获得分发与商用授权的默认角色，至少覆盖待机、左右移动、点击反馈、拖拽、休息这几类动作；动作帧数由角色包清单定义。
- 基于现有小窗口的自动游走，支持暂停。移动范围限制在当前显示器工作区；拖拽后从新位置继续。显示器断开或分辨率变化后，宠物返回可见区域。
- 首次启动直接可玩；保留现有角色切换、聊天、语音和提醒，但不把配置它们作为首次使用条件。
- “我的工具”固定入口，指向 https://next.ganzhibin.icu/ ，并有明确的外部浏览器打开行为。
- 静音、暂停活动、重置位置、退出等常用操作可从菜单到达。
- Windows 与 macOS 完成安装、拖拽、入口和退出的手工验收；Linux 保留现有构建，逐项确认可支持的窗口行为。

### P1 留存与趣味性

- 低频、可关闭的自主动作：打盹、巡视、追视鼠标、玩玩具；不以饥饿或连续签到惩罚用户。
- 免费装饰与多角色切换，形成可分享的桌面截图。
- 专注模式与全屏场景下的自动安静/隐藏，设置中可关闭自动行为。
- 外部产品联动试点：用户主动选择把画图作品设为宠物小窝背景，或在简历完成导出后触发一次庆祝反馈。该联动依赖外部产品提供明确的授权和接口，再单独设计。

### P2 后续探索

- 跨窗口停坐、跨屏游走、自制角色工具和创作者社区。
- 与简历或画图产品更深入的状态联动。
- 现有 AI 对话的体验优化；继续维持可选配置，不成为桌宠基础玩法或推广入口的前提。

## 5. 交互与视觉要求

- 角色在桌面上有清晰轮廓、稳定帧率和可识别的朝向；触摸或拖拽后立即反馈，避免同一动作重复触发。
- 首次使用只提示三件事：拖动宠物、右键打开菜单、从菜单退出。提示可关闭，不反复出现。
- “我的工具”在菜单中保持固定位置。入口写“打开淘气工具铺”，说明为“简历、画图等工具，点开就能用”；不以仓库名代替产品说明。
- 工具入口不使用定时弹窗、自动开浏览器、强制登录、未授权通知或诱导点击的奖励。
- 外部链接打开失败时给出可理解的反馈；宠物仍可正常运行。
- 文案覆盖简体中文、英文和日文，沿用现有国际化机制。

## 6. 技术设计

### 6.1 行为与窗口

新增一个可单独测试的行为模块，输出 idle、walk、interact、drag、rest、focus 等有限状态。事件优先级为用户拖拽与点击、高于专注/暂停、高于自主动作。自主动作由单个调度器驱动，角色切换、暂停或退出时清理定时器。保留现有角色包格式，通过“行为状态 → 角色包动作名”的映射播放动画；缺少某个动作时映射到已有待机动作，不要求所有第三方角色包立即更新。

主进程负责原生窗口坐标、显示器工作区与外部链接；渲染进程负责精灵图绘制、气泡和输入反馈。游走更新窗口位置时以当前显示器的 workArea 为界，避免进入任务栏、菜单栏或屏幕外。优先沿用 src/main.js 的 drag-start、drag-move、drag-end 流程，不建立第二套拖拽系统。

### 6.2 工具入口与归因

首版只注册受控的 toolbox ID，目标固定为 https://next.ganzhibin.icu/ ，标题和说明通过现有国际化机制提供。主进程根据 ID 查表并打开，渲染进程不传任意 URL。可在链接中加入 utm_source=desktop_pet、utm_medium=app、utm_content=toolbox；参数仅表示桌宠入口，不包含聊天文本、设备标识或个人资料。若以后增加简历、画图直达入口，再为每个目标分配独立 ID 与归因参数。

Electron 使用 shell.openExternal 在默认浏览器打开受控地址；禁止让角色包、聊天回复或远端内容直接指定外部 URL。保持主工程的 contextIsolation 和 preload 边界，按 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security/) 限制导航与新窗口。

### 6.3 设置、数据与隐私

继续使用现有设置与角色会话存储，新增“自主活动”“静音”“专注模式”等少量明确设置。既有用户设置迁移后保持原值；新用户使用适合安静办公的默认值。基础桌宠离线可运行；只有用户主动配置并使用 AI 聊天或语音服务时才发起对应网络请求。

首版以淘气工具铺的访问分析和 UTM 归因衡量桌宠带来的访问，再由工具铺及目标产品统计进入简历、画图产品后的开始使用与转化。若未来在桌宠内采集匿名行为数据，先明确事件范围、告知和退出方式，再上线。关键指标为首次启动成功率、次周留存、工具铺入口点击率、目标产品开始使用率与最终转化率。

### 6.4 预计修改位置

| 位置 | 主要改动 |
| --- | --- |
| src/main.js | 首启流程、菜单、行为调度、窗口移动、受控外部链接 IPC |
| src/renderer.js 与 src/index.html | 新动作展示、暂停状态、首次使用提示 |
| src/preload.js | 暴露按工具 ID 打开的最小接口与行为状态接口 |
| src/i18n.js | 工具入口及设置文案 |
| src/settings.js 与 src/settings.html | 自主活动、安静模式等设置 |
| assets/characters | 发布前加入权利明确的角色素材与动作清单 |
| tests 与 tests/run-electron-smoke.cjs | 行为状态、链接 ID、首次启动和窗口交互的必要验证 |

模块在现有文件过长或状态耦合时再拆分。新增纯逻辑优先独立成小模块；不要为了规划中的功能提前重写聊天、语音或全部设置系统。

## 7. AI 实施任务拆分与验收

### 任务 A：基线与品牌准备

核对当前分支、已有改动、许可证和素材说明；保留上游 MIT 声明。明确应用名称、图标、默认角色素材来源，并确认淘气工具铺首页可访问且简历、画图工具可从该站找到。若素材未就绪，先完成代码和占位配置，不把未授权素材发布出去。

验收：开发构建可运行；许可证与第三方素材清单清楚；发布所需信息有明确负责人。

### 任务 B：开箱即用与安静控制

修改首次启动流程，直接显示宠物；聊天和人物设置仍可从菜单进入。加入暂停自主活动、静音与专注模式的状态，并保持设置持久化。

验收：全新配置、离线启动时宠物可互动且无强制弹窗；暂停后无自主移动和主动声音；重启后偏好仍有效。

### 任务 C：行为与游走

参考 DeskCat 的行为状态概念，在主工程加入简洁状态机和小窗口游走；复用现有拖拽流程。处理工作区边界、显示器变化和角色动作缺失映射。

验收：拖拽优先于游走；宠物不会永久停在屏幕外；暂停、切换角色和退出后没有遗留运动定时器；聊天与气泡交互不被自主动作打断。

### 任务 D：免费工具入口

新增“我的工具”菜单、受控的 toolbox 目标 ID、国际化文案和外部浏览器打开行为。目标地址为 https://next.ganzhibin.icu/ ，加入不含个人信息的来源参数。

验收：只有用户点击后才打开淘气工具铺的官方 HTTPS 页面；无法通过 IPC 传入任意 URL；打开失败有反馈；宠物不会退出或被错误覆盖；页面中能继续找到简历和画图工具。

### 任务 E：发布验证

执行 npm run check、npm run test:smoke 与 npm run build；在 Windows 和 macOS 实际验证首次启动、透明窗口、拖拽、工具入口、安静模式和退出。Linux 单独记录窗口管理器差异。检查安装包的应用名称、图标、素材授权和许可声明。

验收：测试通过；关键交互有手工验证记录；默认运行不要求登录或网络；发布包中没有占位 URL。

## 8. 给 AI 编码助手的执行指令

在 Ganzhib/desktop-pet 仓库按本规划书实施。以当前 main 为基线，先检查仓库说明、现有分支和未提交改动；新分支按仓库 AGENTS.md 或用户规则命名，提交信息使用“类型(范围): 中文描述”。每次只完成上面一个任务并提交可审查的改动。以现有 Electron 主工程为唯一实现基础，参考 Ganzhib/deskcat 的行为设计，不直接复制其整屏窗口或关闭上下文隔离的配置。保持桌宠永久免费、离线可用、无强制登录；外部产品入口只在用户点击后打开。完成每项任务后报告改动文件、验证结果及仍需提供的素材。
